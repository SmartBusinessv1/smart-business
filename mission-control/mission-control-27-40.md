## Successor hydration: practical decision habits

- **Read active authority first:** Founder, Sources 00/01+11, 09/12/15/17/18, relevant locked mission artifacts. These historical guides explain *why*, not *what may now be executed*.
- **Verify current GitHub facts:** `main` SHA, PR OPEN/DRAFT/MERGED, changed paths/blobs, acceptance review scope, canonical stage record and any required human merge.
- **Do not repeat accepted work:** A new technical delta warrants only its affected independent recheck; a stale message is not grounds to invalidate unchanged approvals.
- **Technical evidence is not legal or runtime evidence:** An EIS, QA plan or CI pass cannot certify actual RLS/grants, transaction races, qualified Indian legal conclusions, deployed functionality or merchant pilot readiness.
- **Product owner versus technical consumer:** Kernel permissions, Cabinet document access, Stock writers and Notification recipients remain under proper source ownership; downstream features consume rather than invent their contracts.
- **Protect merchant dignity:** AI Assistant, Not AI Judge; Owner financial intelligence protected; employees and external participants have scoped roles; overtime has platform default-OFF activation and remains an approved BUILD NOW recording obligation unless explicitly changed.
- **Make handoffs executable:** Mission Control supplies the eligible next actor, exact room/destination, source pins, permitted task, complete copy/paste instruction, expected finding, GitHub return route and STOP conditions.
- **Prioritize delivery:** At the latest Founder-approved sequencing, finish SB-P-1.18 documentary Stages10–13 and truthful partial-completion/suspension before SB-P-1.12 implementation activation assessment. No parallel implementation solely because historical documents are being published.
