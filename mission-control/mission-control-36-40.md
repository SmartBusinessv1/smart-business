## V. Institutional lessons and successor hydration

1. **History must identify its evidence class.** Direct room transcripts, inherited summaries and later GitHub checks are different. Never invent an MC38/39 conversation attribution from evidence-only links.
2. **Authority-bearing records have multiple gates.** Product/Founder approval, decision record, merge authority, accepted specialist review, source EIS lock, Stage13 package re-lock, implementation authorization and runtime proof are not interchangeable.
3. **Upstream source-owned semantics must be specified upstream.** Kernel permission set reads, Cabinet retrieval, Stock single-writer execution and Notifications non-member recipients cannot be invented by an SB-P-1.18 consumer.
4. **One protected authorization boundary, all channels.** Native, UI, API, AI, WhatsApp and background processing must use server-side current business/action/target authority. Candidate discovery is never outward disclosure permission.
5. **Default-OFF overtime is activation control, not scope removal.** Keep all five approved overtime facets BUILD NOW; don't invent payroll law, enable overtime, waive legal/privacy conditions or quietly exempt the commercial pilot.
6. **Keep staff dignity and the human decision owner.** No AI accusation, autonomous payroll entitlement or hidden Owner financial intelligence leakage through staff workflows.
7. **Security and performance claims need precise kinds of evidence.** A passed Markdown build or accepted EIS is not an actual SQL/RLS/GRANT, race, provider or merchant-runtime test.
8. **Do changed-delta reviews, not endless repeat reviews.** Use exact head/blobs, preserve unaffected specialist findings and refuse ineligible same-context role duplication.
9. **Keep source-record and package status accurate.** A human-merged EIS/source amendment may require a distinct Stage10/Stage11 or Stage13 re-lock record; none of these implies implementation permission.
10. **Make next-actor handoffs complete.** Name eligible actor, existing destination, authorized scope, exact source pins, expected verdict, repository recording method, STOP triggers and return destination.
11. **Respect Founder sequencing.** Finish SB-P-1.18 documentary Stages10–13 and proper suspension first; then assess SB-P-1.12 implementation activation. Do not start parallel implementation because an upstream documentary correction is being prepared.
12. **Protect the application delivery goal.** Use historical lessons to reduce bureaucracy, accelerate bounded work and restore progressive internal testing through the native Conversation Workspace.
