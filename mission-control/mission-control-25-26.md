# 2. Decision Model Learned Across MC25–MC26

Before proposing or accepting the next step, Mission Control should ask:

1. **What was the exact authorized boundary?** An OLE Stage 1 harvester task, a Product Mission lifecycle amendment, manual review, documentation publication and SB-P-1.12 activation are different scopes.
2. **What state is actually reached?** Proposal, branch, merged implementation, test run, independently verified learning, candidate, validated OLE promotion, activated governance, closed mission and current production state must not be conflated.
3. **What earlier authority is superseded, and from what instant?** Prepared amendments did not activate Source 18 v1.2; the human merge of PR #608 did.
4. **What decision belongs to the Founder?** The Founder chooses product direction, approves defined gates, directs Drive retirement and manual-backfill policy, and merges protected-main PRs; Mission Control cannot manufacture that authority.
5. **Does a correction change substance or just evidence language?** If only publication metadata is stale, do not rewrite history or re-open product design.
6. **What is the accepted prerequisite, and what extra work is merely useful?** OLE implementation was a prior prerequisite; *historical OLE backfill* was later explicitly kept manual and is **not** a new prerequisite for SB-P-1.12.
7. **Can we explain why the technical state changed?** The same Supabase ref was test-only before becoming production; the current test ref is different. Historical context prevents unsafe mis-targeting.
8. **Will the next room know where to resume?** Provide current main SHA, last relevant merged PR, controlling documents, open risks, scope flags and a precise next *authorized* action.
9. **Is the document about decisions or merely a PR list?** Write the causal story and judgement; use PR numbers as checkable evidence.
10. **Are we silently turning a planning estimate into a deadline?** Product Mission duration is provisional until the source-contract and implementation Delta have been reconciled.

### Why the decision quality matters

The OLE should reduce repeated research, not displace Founder judgement. Mission learning needs provenance pinned to real committed evidence; eligibility to read a file does not mean the file is governing truth; the generator cannot independently validate its own assertions. Future room context should prefer current validated learning and traceable sources, keeping contested, stale, superseded and provisional lessons distinct.

The earlier MC24 insistence on manual/supervised **proof-stage** extraction and eventual guarded background candidate processing was an engineering-sequencing choice, not permission for autonomous approval.

### Inherit

- Separate organizational learning from current Product Truth.

- A tool's technical capability to create or modify a file does not grant Git, Product Mission, release or governance authority.

### B. Reconcile the Product Mission lifecycle against real operational failures

The \`SB-GOV-PRODUCT-EXEC-1.0\` sequence tightened Source 18 and its related templates/protocols. The key changes were:

- A mission Intake Pack grounded in actual contract identities, an institutional-learning record and current repository state.

- Stage 8 Blueprint lock, Stage 11 EIS lock, Stage 13 package lock and separately recorded implementation authorization.
- Mandatory Founder/human runtime findings, independent coverage/drift verification, finding-scoped correction with human retest, and per-row reconciliation before acceptance.
- OLE disposition and residual carry-forward before formal closure.
- Explicit default-deny **production mutation, migration execution, delivery sync and publication** boundaries in a Product Mission.

Evidence: current \`merge/active/18_SB-P_Mission_Lifecycle_and_Delivery_Framework.md\`; [PR #605](https://github.com/SmartBusinessv1/smart-business/pull/605), [#606](https://github.com/SmartBusinessv1/smart-business/pull/606), [#607](https://github.com/SmartBusinessv1/smart-business/pull/607).

1. Calling a prepared governance PR an activation when the designated human-merge event has not occurred.
2. Calling an OLE candidate a validated organizational lesson without the separate promotion record.
