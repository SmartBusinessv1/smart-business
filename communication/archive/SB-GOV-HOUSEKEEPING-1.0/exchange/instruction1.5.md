## 2. Project HQ content verification

For every Project HQ source, Mission Control shall compare the available Project HQ content with the current GitHub source and verify, at minimum:

- filename;
- document title or identifying header;
- source number or binding decision identity;
- declared version and status where present;
- authority metadata where present;
- opening purpose and authority sections;
- material section coverage;
- terminal status or authority control where present;
- absence of obvious truncation, substitution, stale predecessor content, or manual rewriting.

Where the Project HQ file interface exposes the complete raw file content, Mission Control shall perform exact-content or hash comparison where possible.

Where the Project HQ interface does not expose raw bytes or downloadable files, Mission Control shall clearly distinguish:

```text

```

```text

```

Mission Control shall not claim byte-for-byte identity without sufficient evidence. If exact byte verification is required but unavailable through the Project HQ interface, the Founder may provide an exact ZIP or the original uploaded files for hash comparison.

## 3. GitHub verification

Mission Control shall verify the current `main` branch and confirm:

- repository: `SmartBusinessv1/smart-business`;

- canonical count: 20 Markdown files;

- current commit containing the canonical package state;
- package membership matches the permanent manifest;
- no canonical source was silently added, removed, renamed, or reclassified after the last verified baseline without an approved mission;
