## Important Technical Judgements

- Canonicalization is an evidence problem before it is a file-movement problem.
- Historical evidence, current authority, and executable authority are separate classifications.
- Exact scope and deterministic inventories make large documentation changes reviewable.
- Capability does not equal authority; automation remains mission-, actor-, branch-, path-, and stage-scoped.
- A correct no-op or preservation decision is preferable to ceremonial rewriting.

## Mistakes / Weak Assumptions / Corrections

- **MISTAKE / FAILURE MODE:** Treat every `pending` or draft phrase as current work. **→ CORRECTION:** Classify by lifecycle and provenance. **→ DURABLE LESSON:** Search hits need authority context.
- **MISTAKE / FAILURE MODE:** Resolve ambiguity by silently choosing a source. **→ CORRECTION:** Maintain a conflict register and obtain Mission Control/Founder disposition. **→ DURABLE LESSON:** Technical review reveals conflicts but does not gain decision authority.
- **MISTAKE / FAILURE MODE:** Delete or rewrite legacy sources during canonicalization. **→ CORRECTION:** Contain them with integrity evidence and preserve historical references. **→ DURABLE LESSON:** Historical continuity and current authority can coexist.
- **MISTAKE / FAILURE MODE:** Grant broad automatic Git power. **→ CORRECTION:** Bind actor, mission, repo, branch, paths, commit message, verification, and expiry. **→ DURABLE LESSON:** Safe automation is narrow and revocable.
