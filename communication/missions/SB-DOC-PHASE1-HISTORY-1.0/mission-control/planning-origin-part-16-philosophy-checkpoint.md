## 2. Part 16 contribution

Part 16 contributes an **execution philosophy** more than abstract institutional philosophy.

Key items to preserve:

- preparing future operating packs does not authorize future execution;
- role-specific context is preferable to indiscriminate context;
- calibration should test behaviour, restraint, security, and scope before execution;
- existing sources should be mapped and reused before duplicate sources are created;
- external systems should be activated deliberately by project state, not because accounts/tools are available;
- non-technical decision owners should receive guided execution instructions and proof requirements;
- data ownership and RLS should precede convenience;
- file storage should preserve ownership, permissions, purpose, and lifecycle;
- AI should remain an assistant and avoid prescriptive/judgmental business decisions;
- payment failure should not become sudden destruction of customer history;
- preparation/documentation must stop once it has reduced uncertainty enough for execution to resume;
- environment activation becomes the bridge from planning intelligence to real-world execution tools.
