## Purpose

Create a durable verification protocol before the Smart Business Product Mission program accelerates, so independent-verifier capacity is used for high-value adversarial assurance instead of duplicating deterministic CI work.

The protocol must preserve rigor while reducing unnecessary repeated verifier execution.

## Founder design basis

The Founder-approved design direction requires:

- Codex as a scarce independent verifier, not a builder;
- deterministic checks owned by CI;
- builder Verification Packets before independent review;
- risk-based Codex involvement;
- evidence classes for independent execution, automated-evidence inspection, and static inspection;
- finding-scoped re-verification by default;
- full re-verification only after broad/shared changes or explicit Mission Control direction;
- documentation-only follow-up commits not reopening substantive independent verification;
- Mission Control/human acceptance authority preserved;
- independent verification treated as an actor-separation property rather than silently hard-coding one provider where governance permits.
