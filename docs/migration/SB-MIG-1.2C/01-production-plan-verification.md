## 2. Billing Tier

**Confirmed via `get_organization`: the organization's plan is `free`.**

This is the single most consequential finding in this document. Supabase's free tier does not include the backup/recovery capabilities a production system requires:

- **No Point-in-Time Recovery (PITR)** — PITR is a paid add-on available only on Pro-tier-and-above projects.
- **No scheduled daily backups** — daily backups (7-day retention) are a Pro-plan-and-above inclusion; the free tier has no platform-managed backup product at all.

This is stated with high confidence based on Supabase's publicly documented plan structure, not from a live "backup status" API — no tool available in this environment queries backup/PITR configuration directly (§3 explains this limitation and how it was worked around for what *is* directly observable). **A human with dashboard access should independently confirm this by opening Project → Database → Backups**, both to verify the plan-derived conclusion above and because plan-to-feature mappings can change over time.

## 3. Backup, PITR, and Recovery Window

No MCP tool in this environment exposes backup schedule, PITR window, or recovery-point status directly (`restore_project` is a destructive action tool, not a status-check tool, and was not invoked). This is a genuine tooling gap, stated plainly rather than worked around — consistent with this mission's instruction not to route around stop conditions.

**Inference from the confirmed `free` plan (§2): backups and PITR are almost certainly unavailable on this project today.** This is treated as the working assumption for the remainder of this mission's documents (`02-backup-recovery-report.md` in particular) until a human confirms otherwise via the dashboard.
